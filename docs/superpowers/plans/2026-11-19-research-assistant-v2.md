# Research Assistant v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the v1 three-agent CrewAI crew into a CrewAI Flow with a pre-research router, tiered deep search, a Dockerised scrape/parse/render worker, size-controlled reports, and an optional PDF flow with real-data charts.

**Architecture:** `ResearchFlow` (CrewAI Flow) runs router → tier-specific research → analysis → writer (Markdown, or PDF when selected). Every tool records sources in a per-run `SourceRegistry`; citations are validated against it. A FastAPI worker container hosts Crawl4AI (`/scrape`), Docling (`/parse-pdf`) and Chromium (`/render-pdf`). Streamlit runs natively and talks to the worker over HTTP.

**Tech Stack:** Python 3.12, uv, crewai[litellm], crewai-tools, pydantic v2, httpx, Jinja2, matplotlib, FastAPI, Crawl4AI, Docling, Playwright (Chromium), Streamlit, pytest.

**Spec:** `docs/superpowers/specs/2026-11-19-research-assistant-v2-design.md`

## Global Constraints

- Python `>=3.12`; dependencies managed with uv (`uv add`, `uv run pytest`).
- Models through OpenRouter via LiteLLM; every role reads `<ROLE>_LLM` / `<ROLE>_TEMP` from `.env`; PDF-mode overrides use the `_PDF` suffix and fall back to the base variable.
- Role env names: `ROUTER_AGENT_LLM`, `RESEARCH_AGENT_LLM`, `ANALYST_AGENT_LLM`, `WRITER_AGENT_LLM`, `FIGURE_PLANNER_LLM` (each with `_TEMP`; PDF overrides e.g. `WRITER_AGENT_LLM_PDF`).
- Tiers 0–3 with default caps (searches/pages/PDFs/Firecrawl credits): T0 2/0/0/0, T1 5/8/0/0, T2 8/15/5/0, T3 15/30/10/100. PDF mode multiplies caps by 1.5 (ceil); Big size multiplies page and PDF caps by 1.25; never exceed Tier 3's caps times 1.5 for searches, pages, PDFs.
- PDF mode or Big size bumps Tier 0 to Tier 1; router parse failure falls back to Tier 1 with a warning.
- Report sizes (body words): Small 800–1,200; Medium 2,000–3,000 (default); Big 5,000–7,000. PDF tables/figures: Small 1/1–2, Medium 2/3–4, Big 4/6–8. Word-count tolerance ±15%, one expand/trim pass.
- Citations are `[S<n>]` IDs from the registry; the reference list is generated by code; unknown IDs fail once then are stripped and logged.
- Chart specs must reference a data table file; no data reference means rejected.
- Respect robots.txt; never bypass paywalls; use Unpaywall open-access copies only.
- Run output goes to `runs/<run_id>/`; nothing is written to the project root.
- Free tools by default; Firecrawl only if `FIRECRAWL_API_KEY` is set, only at Tier 3, only as fallback.

## Review Focus

- Empty or whitespace-only topic: UI and flow must refuse it rather than call the router.
- Router returns malformed JSON, an unknown tier, or budgets above the hard caps: fall back or clamp, never crash.
- Worker down or `/scrape` times out: research continues with snippets and the coverage notes record the failure.
- Writer cites `[S99]` that does not exist: validator strips it and logs it, the report still builds.
- A source with no DOI and a URL differing only by trailing slash or `#fragment`: registry must not duplicate it.
- Chart spec referencing a missing or empty data file, or with non-numeric values: rejected with a logged reason; the report builds without that figure.
- Topic containing non-ASCII characters or path-like text (`../`): run folder names must stay inside `runs/`.
